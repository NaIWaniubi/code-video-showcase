用代码做片子的工作台

一句话生成设计稿，改文案、微调画面、编译成片、逐帧检查。 所有界面都在本机运行，不上传素材。

打开向导，开始做片 → 界面入口在 http://127.0.0.1:5180/app/（cvs ui 启动后）
也可以全命令行（本仓库命令统一写成 node bin/cvs.mjs <命令>，npm link 后可用 cvs 短写）：
$ node bin/cvs.mjs new "做一个 30 秒赛博像素宣传片" --out project.spec.json
$ node bin/cvs.mjs build project.spec.json
第一次用？先跑 bash install.sh（Windows：powershell -ExecutionPolicy Bypass -File install.ps1）。

六个界面

用 node bin/cvs.mjs ui 启动时都在这个端口下（帧 API / 评审反代齐全）；卡片直接点就能进，命令只是另一种启动方式

从零到成片

每一步都可以停下来看结果，不满意就回去改
  1. 生成设计稿cvs new "…" --out project.spec.json或用向导下载，放到仓库根。
  2. 校验cvs lint project.spec.json --root .检查页面、主题、对比度、占位符。
  3. 改内容node bin/cvs.mjs script改完点「下载」，把浏览器下载的文件放回仓库根目录同名覆盖 project.spec.json（浏览器不会自动替换）；画面问题去画布。
  4. 编译node bin/cvs.mjs build project.spec.json产物 out/master.mp4，同时会在 out/ 写出 plan.json（分段时间表，质检要用）；增量渲染只重跑改过的段。
  5. 检查node bin/cvs.mjs qa out/master.mp4 --plan out/plan.jsonplan.json 是上一步 build 生成的；再开帧预览逐帧看，或发给同事评审。
  6. 交付cvs deliver成片 + 字幕 + 封面 + 清单；需要留底就 cvs snapshot。

几个名词

界面里出现这些词时，指的是——
spec
片子的设计稿（一份 JSON），是唯一入口。文案、风格、时长、结构都在里面。
plan
由 spec 派生的分段时间表：每段用哪个页面、多长、从第几帧到第几帧、内容 hash。
段 / segment
一支片子由若干段拼成。每段 = 一个页面在一个时间区间里的渲染。
帧号
第 n 帧的时刻是 n / fps 秒。预览、导出、质检都以帧号对齐。
成片
out/master.mp4。母版 1920×1080，平台版本是附加文件。
recipe
风格配方 id（如 recipe-flat）。剧本表格里给每段指定画面风格用。
改动 / patches
画布里点选元素做的修改，导出成 spec.patches.json 后可回放到 spec，不用重画。
